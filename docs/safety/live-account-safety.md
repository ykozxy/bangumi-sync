# Live Account Safety

Status: required guardrail for Rust v2 development.
Date: 2026-06-11

## Default Rule

Development must not modify personal Bangumi, AniList, or MyAnimeList account data unless the user explicitly approves a specific live-write test.

Rust v2 Phase 0 and Phase 1 are read-only and dry-run only.

## Existing TypeScript Baseline

The existing TypeScript runtime can write to AniList collection data.

Treat these commands as unsafe for Phase 0 unless the user explicitly approves the run:

- `npm start`
- `npm run start-server`
- `node build/main.js`
- `node build/main.js --server`

The safe TypeScript baseline verification command is:

```bash
npm run build
```

## Rust v2 Safety Rules

Rust v2 commands must default to dry-run behavior.

Allowed during Phase 0 and Phase 1:

- Fixture imports.
- Local model tests.
- CLI help and read-only skeleton commands.
- Mock HTTP tests.
- Read-only provider snapshot code once implemented.
- Local OAuth auth-session files generated by `sync-v2 auth begin`.
- Passphrase-encrypted local credential bundles when populated only through
  fixture token transports.

`auth begin` session files are local auth-broker bookkeeping, not credential
bundles. They may contain OAuth `state` and MyAnimeList PKCE verifier material,
so they should be short-lived, owner-readable only, and never committed. They
must not contain access tokens, refresh tokens, browser cookies, CSRF tokens, or
provider session data.

`auth begin` and `auth authorize-url` suppress authorization URLs by default.
Passing `--show-sensitive-authorization-url` is an explicit opt-in to print URL
material that may contain OAuth `state` and, for MyAnimeList, the plain PKCE
verifier as the `code_challenge`. Treat any output or logs created with that
flag as temporary secret material; do not commit or share them.

`--test-credential-bundle` uses a reversible fixture codec and is never a
production credential store. `--credential-bundle` must use the passphrase
encrypted file codec and must receive its passphrase from an environment
variable. Do not commit credential bundles, passphrases, token response fixtures,
or auth-session files.

Disallowed without explicit user approval:

- Creating, updating, or deleting real collection entries.
- Deleting remote entries on any provider.
- Overwriting notes, comments, tags, or private metadata.
- Running write tests against personal accounts.
- Using browser sessions to mutate personal collection data.

## Live Test Policy

Provider write tests must use this order:

1. Unit tests and golden-file dry-run plans.
2. Mock HTTP provider tests.
3. Throwaway Bangumi, AniList, and MyAnimeList accounts.
4. Small allowlisted live-write batches only after explicit user approval.

Deletes remain disabled by default even after write support exists.

## Local Build Note

This repository may live in a OneDrive-backed directory. If `npm run build` fails because `node_modules/.bin` command shims contain plain relative path text instead of symlinks, repair the local ignored `node_modules/.bin` entries before treating the TypeScript build as a source failure.
